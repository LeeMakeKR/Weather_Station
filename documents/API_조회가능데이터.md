응답에는 발표일시·격자·자료구분과 `obsrValue`(실황) 또는 `fcstValue` 및 예보일시(예보)가 포함된다. 초단기 `POP`는 문서상 2026-06-23 11KST 이후 확대 제공 항목이다. 문서 안내문에서 POP를 “강수형태”로 표기한 부분이 있으나 코드표의 “강수확률”을 기준으로 정리했다.

단기예보는 02/05/08/11/14시 발표 기준 글피까지, 17/20/23시 발표 기준 그글피까지 제공한다. 연장 구간은 3시간 간격이며 `PCP`, `SNO`, `WSD`는 정성정보 코드로 제공한다. 일반 구간의 수치·범주와 구분해 해석해야 한다.

강수량·적설은 범주/문자열일 수 있으므로 일괄 실수 변환하지 않는다. 결측값 및 해상 마스킹을 처리하고 모든 격자에서 모든 항목이 제공된다고 가정하지 않는다. 여러 시간·항목을 받으려면 `totalCount`에 맞춰 페이지를 조회한다.

최신 첨부 가이드는 기상청 API허브의 `https://apihub.kma.go.kr/api/typ02/openApi/VilageFcstInfoService_2.0/`와 `authKey`를 사용한다. 현재 코드의 공공데이터포털 URL·`serviceKey`와 인증 체계가 다르므로 혼용하지 않는다.

공통 시간 조건은 `tmFc=YYYYMMDD0600` 또는 `YYYYMMDD1800`이다. 첨부 문서의 육상·기온·해상 조회 범위는 **06시 발표: 4~10일 후, 18시 발표: 5~10일 후**이다. 단기예보와 날짜 기준으로 이어 붙여 주간 화면을 구성한다. 없는 날짜나 오전·오후 필드를 임의로 생성하지 않는다.

`stnId`와 세 종류의 `regId`는 서로 대체할 수 없다. 예: 서울은 전망 `109`, 육상 `11B00000`, 기온 `11B10101`; 해상은 별도의 해역 선택이 필요하다. 상세 기온 지역은 DOCX의 대표 도시 표보다 첨부 XLSX를 우선한다.

## 구현 시 데이터 처리 기준

1. 위치 변환 결과와 API별 조회 조건을 분리하고, 지역명·측정소명·구역코드의 용도를 구분한다.
2. HTTP 응답과 API 결과코드를 확인한 뒤 JSON/XML을 파싱한다. 페이지 수는 `totalCount`로 판단한다.
3. 결측·점검 상태를 0으로 표시하지 않는다. 농도·등급·날씨코드·문자열 범주는 각 규격대로 처리한다.
4. 표시값에 관측/발표/예보 대상 시각을 연결한다. 실시간 관측과 예보, 지역 평균은 구분한다.
5. 화면에 필요한 현재 관측·오늘 예보·주간 예보·PM10/PM2.5부터 선택한다. 나머지는 확장 기능으로 둔다.
